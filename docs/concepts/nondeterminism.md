# 非決定性

## 一言でいうと

ある状態から次に何が起きるかが，1つに決まらないことである．
仕様では，「どれが起きてもよい」ものを非決定的に書き，そのすべての可能性を検査の対象にする．

## 例

自動販売機に，2人が同時に近づく場面を考える．
どちらが先にボタンを押すかは，システムには決められない．
仕様では「Aさんが押す」「Bさんが押す」のどちらも起きうると書く．

非決定性は，次のような場面で現れる．

- 複数の利用者の操作の順番．
- 外部システムの応答(成功と失敗のどちらになるか，いつ届くか)．
- 時間の経過(時間切れがいつ起きるか)．

## なぜ必要か

実際のシステムでは，操作の順番や外部の応答を開発者が選べない．
仕様で1つの順番だけを書くと，それ以外の順番で起きる問題を検査できない．
非決定的に書くと，検査は起こりうるすべての選び方を調べる．

## 非決定性と確率の違い

非決定性は，「どちらかがランダムに選ばれる」という意味ではない．
「どちらが選ばれても成り立たなければならない」という意味である．
めったに起きない順番も，よく起きる順番と同じように調べる対象になる．

## テストとの違い

テストでは，順番を1つに決めて書く．
非決定的な仕様では，テストで書かなかった順番も調べる．
テストで同時に起きる操作の問題を再現するには，その順番を狙って書く必要があるが，検査では狙う必要がない．

## よくある誤解

- `quint run`がランダムに選ぶのは，すべての選び方を調べる時間がないからである．仕様の意味としては，すべての選び方が起きうる．
- 非決定性は，仕様があいまいだということではない．起きうることの範囲を，正確に書いたものである．

## Quintでの書き方

`nondet 名前 = 集合.oneOf()`で，集合の要素を1つ非決定的に選ぶ．
`any { ... }`で，並べたアクションのどれかが起きることを表す．
