# テスト・シミュレーション・モデル検査

## 一言でいうと

3つとも仕様や実装の誤りを見つける方法だが，調べる実行の範囲が違う．

| 方法 | 調べる実行 | Quintのコマンド |
| --- | --- | --- |
| テスト | 書いた手順の1つの実行 | `quint test` |
| ランダムシミュレーション | ランダムに選んだ多数の実行 | `quint run` |
| モデル検査 | 決めた範囲のすべての実行 | `quint verify` |

## テスト

テストは，手順と期待する結果を書き，その1つの実行を確かめる．
手順を書く人が思いついた実行しか調べられない．
要求文の例は，ほとんどが「うまくいく場合」なので，例をテストにしただけでは要求の抜けは見つからない．

## ランダムシミュレーション

ランダムシミュレーションは，初期状態から遷移をランダムに選び，実行を作る．
これを多数回繰り返し，性質が破れる実行を探す．

- 速く，大きな仕様でも動く．
- 反例が見つかれば，それは確かに起きうる実行である．
- 見つからなくても，性質が成り立つとは限らない．選ばれなかった実行の中に，反例が残っていることがある．

## モデル検査

モデル検査は，決めた範囲のすべての実行を調べる．
範囲とは，ステップ数の上限や，顧客・注文の数などの定数である．

- 範囲の中に性質を破る実行があれば，必ず見つける．
- 範囲を広げると，調べる状態が急に増え，時間がかかる．
- 反例は，多くの場合最も短いものが示されるので読みやすい．

## 使い分け

1. 仕様を書いたら，`quint test`で要求文の例どおりに動くことを確かめる．
2. 性質を書いたら，`quint run`で素早く反例を探す．
3. `quint run`で見つからなくなったら，`quint verify`ですべての実行を調べる．

## よくある誤解

- テストが通ることは，仕様が正しいことを意味しない．書いた手順で期待どおりに動くことを意味するだけである．
- モデル検査で性質が成り立っても，範囲の外で破れることはある．範囲の選び方はIteration 6で扱う．
- モデル検査は仕様を調べる．実装が仕様どおりかは，別に確かめる必要がある．Iteration 7で扱う．
