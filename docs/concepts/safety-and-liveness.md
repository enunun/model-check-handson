# 安全性と活性

## 一言でいうと

仕様の性質は，大きく2種類に分かれる．

- 安全性：悪いことが決して起きない．
- 活性：良いことがいつか必ず起きる．

## 例

エレベーターで考える．

| 種類 | 例 |
| --- | --- |
| 安全性 | 移動中は扉が開かない．定員を超えて乗せない． |
| 活性 | 呼び出しボタンを押せば，いつかエレベーターが来る． |

何もしないエレベーターは，安全性をすべて満たす．扉は開かず，誰も乗せないからである．
しかし，呼んでも来ないので，活性を満たさない．
安全性だけを検査すると，「何もしない」という誤りを見逃す．

## 反例の形

| 種類 | 反例 |
| --- | --- |
| 安全性 | 悪いことが起きた状態までの，有限の状態の列 |
| 活性 | 良いことがいつまでも起きない，無限に続く実行．同じ状態に戻る輪(ループ)や，何も起きずに止まり続ける状態(スタッタリング)で示される |

安全性の反例は，途中までの手順を見せれば誤りを示せる．
活性の反例は，「この先も良いことは起きない」ことを示すために，終わりのない実行を示す．

## なぜ必要か

要求文の「いずれ」「必ず」「いつまでも〜ない」は，活性を表す．
これらは，テストでは確かめられない．テストは有限の手順しか実行できず，「いつか起きる」を確かめるには，いつまで待てばよいかが決まらないからである．
活性を性質として書くと，処理が途中で止まる，同じところを回り続けるといった誤りを検査できる．

## テストとの違い

テストでは「この手順のあとで確定している」は確かめられるが，「どんな手順でも，いつか確定する」は確かめられない．
テストで時間切れを設けても，それは「決めた時間内に起きる」という別の性質を確かめている．

## よくある誤解

- 安全性が成り立っても，システムが正しく動くとは限らない．何もしないシステムでさえ，安全性を満たす．
- 活性の反例は，「そのうち起きる可能性がある」という意味ではない．その実行では，良いことが永遠に起きない．

## Quintでの書き方

安全性は不変条件(`val`)で，活性は時相論理の性質(`temporal`)で書く．
